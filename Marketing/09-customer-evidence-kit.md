# Customer evidence kit

Status: Collection material. No verified customer results or approved quotes were supplied. Do not publish this file as a customer story.

## Case study interview

Record the interview date, interviewer, customer name, role, and permission to record notes. Ask these questions:

1. What customer requirement caused the deployment work?
2. What process did you use before Deployz?
3. Which app architecture did you test?
4. What changes did the app need?
5. What worked, and what did not work?
6. How did you confirm the installation was ready?
7. Which result can you support with records?
8. What limits should a similar team understand?

## Evidence record

For each result, record the source, date range, unit, baseline, final value, and method. Keep setup time separate from AWS resource creation time. Keep Deployz fees separate from AWS costs. Record code changes and human work. Do not use one test result as a promise for all apps.

Keep customer records in the customer's approved system. Put only approved public summaries in this folder.

## Case study structure

- Customer and approved attribution.
- Requirement and application architecture.
- Previous process.
- Deployment process and app changes.
- Verified results with the measurement period.
- Limits, lessons, and next step.

The PDF worksheet provides blank fields for this record. It is an internal form, not finished customer evidence.
