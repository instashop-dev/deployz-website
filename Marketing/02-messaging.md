# Messaging

## Main message

Deploy your SaaS into customer AWS.

## One sentence

Deployz helps SaaS teams deploy and update supported apps in their customers' AWS accounts.

## Short description

Your customer wants your app in their AWS account. Deployz checks your GitHub repository, helps you prepare a release, and sets up supported AWS infrastructure. Send an installation link. Your customer reviews and approves AWS access. You choose the release for each customer.

## Longer description

Deployz gives small SaaS teams a process for customer AWS deployments. Connect GitHub with read-only access. Review the readiness report, provide settings, and fix blockers in your code. Build a release and test it in your own AWS account.

For a customer installation, send a link. The customer reviews the resources, cost estimate, and requested permissions. They approve a connector in their AWS console. Deployz creates the supported infrastructure and deploys the release.

You manage release selection, updates, rollbacks, and status from Deployz. Your customer owns the AWS resources and pays AWS directly. Deployz fees are separate.

## Three supporting messages

| Message | Support | Limit to keep clear |
| --- | --- | --- |
| Use one installation process for customer AWS | Shared installation links and supported infrastructure setup | Some apps need code changes first |
| Choose each customer's release | Versioned releases, updates, and rollbacks | Rollbacks do not reverse database migrations |
| Keep resource ownership with the customer | App resources run in the customer's AWS account | External integrations still control where they send data |

## Audience copy

For SaaS founders: A customer AWS request can require a new deployment process. Use Deployz to check your app, prepare a release, and manage supported customer installations.

For technical leads: Start with a readiness report. Review the detected needs, fix blockers, and test one supported architecture before customer installation.

For AI app teams: Run your supported API, workers, database, and file storage in customer AWS. Review the data sent to external model APIs and other integrations.

## Writing rules

Use short sentences and direct verbs. Name AWS when you describe cloud support. Explain BYOC as “bring your own cloud” on first use, then state that Deployz currently supports AWS. Use one main action per asset.

Do not invent customer names, results, testimonials, savings, or deployment times. Do not promise a sale, compliance, or support for every app. Use product limits from the claims file.
